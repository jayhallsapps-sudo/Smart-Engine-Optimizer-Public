You are fixing the QBS generator and audit workflow at the system level. This is not a client-specific patch. This is a foundational correction to how the system gathers truth about a website.

The current behavior is wrong whenever it relies too heavily on Screaming Frog to determine what pages exist, how the site is structured, what is in the menu, or what pages should map into report sections.

That must stop.

PRIMARY OBJECTIVE

For every QBS audit, the system must treat the live website and live sitemap as the primary source of truth for:
- site structure
- page inventory
- menu / nav items
- footer links
- actual live URLs
- page intent
- whether a page is truly a Level of Care page, Verify Insurance page, Contact / Admissions page, About page, Team page, Primary Location page, etc.
- page-level content identity
- internal linking presence
- whether the page is actually what the slug suggests it is

Screaming Frog must be used primarily for technical audit context, not as the sole or dominant source for what pages exist on the site.

==================================================
NON-NEGOTIABLE SOURCE HIERARCHY
==================================================

For any audit question involving the website itself, use this hierarchy:

1. LIVE WEBSITE CRAWL + LIVE SITEMAP = PRIMARY SOURCE OF TRUTH
Use these to determine:
- what pages exist
- what pages are linked in nav / footer
- what the actual URLs are
- what the actual page titles / H1s / page purposes are
- whether a page is live
- whether a page is a Level of Care page, utility page, trust page, location page, blog/resource page, etc.
- whether internal links exist between key pages
- whether a page is reachable and structurally part of the site

2. GA4 + CALL TRACKING = PRIMARY SOURCE OF TRUTH FOR CONVERSIONS
Use these to determine:
- top converting pages
- top converting sources
- top conversion patterns
- page-level conversion support
- where real business actions are happening

3. GSC = PRIMARY SOURCE OF TRUTH FOR ORGANIC DEMAND / VISIBILITY
Use this to determine:
- top traffic topics
- top traffic pages
- query intent
- organic visibility patterns
- whether traffic is informational vs care-intent / modality-intent

4. SCREAMING FROG = TECHNICAL AUDIT / STRUCTURAL SUPPORTING SOURCE
Use SF to determine:
- indexability
- status codes
- canonicals
- noindex
- redirects
- internal link counts if useful
- technical warnings / issues / errors
- template / crawl diagnostics
- supporting structure context

Do NOT use Screaming Frog as the sole or dominant source for:
- full site page inventory
- whether a core page exists
- whether a page belongs in a report slot
- whether nav items exist
- whether a page is truly the page the system thinks it is

==================================================
CORE SYSTEM CORRECTION
==================================================

The system must perform a true website crawl for every QBS generation.

Not a shallow slug scan.
Not just homepage extraction.
Not just sitemap URL collection.
Not just Screaming Frog import parsing.

A true crawl means:

- start from the live website homepage
- extract and follow internal links
- inspect main navigation
- inspect footer navigation
- inspect major site sections
- inspect sitemap URLs
- resolve key page templates
- fetch the page itself, not just the slug
- inspect page title, H1, and meaningful visible page content
- use page content and structure to determine page identity
- confirm whether the page actually matches its URL meaning

Example:
Do not assume a page is Detox just because the slug contains detox.
Confirm it by checking page title / H1 / visible content.

Likewise:
Do not fail to detect a detox-related page just because the slug says detoxification instead of detox.
The system must inspect the page itself and classify it correctly.

==================================================
REQUIRED CRAWL BEHAVIOR
==================================================

For every QBS run, the crawler must gather and use:

A) SITE INVENTORY
- all crawlable internal page URLs discovered from:
  - homepage
  - main nav
  - footer
  - sitemap
  - recursively followed internal links
- normalized live page inventory
- deduplicated canonical page list where possible

B) PAGE IDENTITY SIGNALS
For each important candidate page, inspect:
- URL
- page title
- H1
- meta title if available
- visible page content excerpt
- nav / footer link presence
- internal-link context if useful

Use these signals together to classify the page.
Do not classify from slug alone unless there is no better signal.

C) STRUCTURAL SIGNALS
- whether the page appears in nav
- whether it appears in footer
- whether it appears in sitemap
- whether it is internally linked from key pages
- whether it is reachable from homepage in a reasonable number of clicks
- whether it looks like a core conversion-support page vs an orphan vs a blog/resource page

D) TECHNICAL SIGNALS
From Screaming Frog and/or direct page checks:
- status code
- indexability
- noindex
- canonical
- redirect behavior
- internal-link counts if helpful
- technical issues relevant to the page
