Improve QBR Prep Section 2 — Top Converting Pages so it prioritizes real conversion evidence over traffic-proxy fallback rows.

The recent structural fix was good:
- 3-column layout is better
- source badges on Type are better
- Page / Pattern is cleaner
- Notes / What We’re Learning is better

But the row-selection logic still needs improvement.

Right now, the table can still end up leaning too heavily on GSC fallback rows like:
- Blog / Resource [GSC]
- Homepage [GSC]

That is structurally cleaner than before, but it is still not ideal for a section called “Where Conversions Actually Happen.”

This section should strongly prefer rows backed by actual conversion or call behavior before it falls back to traffic proxies.

==================================================
GOAL
==================================================

Refine the Top Converting Pages row-ranking logic so the table prefers real conversion evidence in this order:

1. GA4 conversion/event-backed rows
2. Call tracking landing-page/call-backed rows
3. GBP / local-entry-backed rows where defensible
4. Priority service/admissions pages used as fallback only when tracked conversion rows are insufficient
5. GSC visibility-proxy rows only as last-resort filler

The table should feel like:
“where conversions are actually happening”
not
“where traffic exists”

==================================================
PRIORITY ORDER TO IMPLEMENT
==================================================

Use this strict ranking priority for candidate rows:

Priority 1 — GA4-backed rows
Examples:
- Form Entry [GA4]
- Service Page [GA4]
- FAQ Page [GA4]
- Homepage [GA4]
- Staff Page [GA4]

These should rank highest when tied to:
- form_start
- generate_lead
- submit_form
- phone_click
- call_click
- verify_insurance events
- other clearly conversion-relevant event patterns

Priority 2 — Call tracking backed rows
Examples:
- Homepage [CallRail]
- Service Page [CTM]
- Contact / Admissions [CallRail]
- Verify Insurance [Nimbata]
Use these when landing-page/source attribution is real enough to support a page row.

Priority 3 — GBP/local-entry-backed rows
Only use when there is defensible evidence that GBP is a primary call/click entry path and the page association is meaningful enough.

Priority 4 — Priority service page fallback
Use configured money pages / service pages / admissions pages only when real tracked page-level conversion rows are insufficient.
These rows should be clearly client-safe but lower priority than true GA4/CTM/CallRail rows.

Priority 5 — GSC visibility-proxy fallback
Use GSC rows only as last resort filler.
They should not dominate the table if better evidence exists.

==================================================
ROW SELECTION RULES
==================================================

Implement scoring/ranking so:
- any GA4 row with real conversion/event evidence outranks a GSC-only row
- any call-tracking-backed page row outranks a GSC-only row
- GSC fallback rows should only appear when the table still needs more usable rows after higher-confidence sources are exhausted
- avoid filling the table with multiple weak blog/GSC proxy rows if stronger service/contact/form rows exist

Prefer rows that are:
- directly conversion-linked
- call-linked
- admissions-linked
- verify-insurance-linked
- service-intent-linked
- contact-intent-linked

De-prioritize rows that are:
- purely informational
- blog/resource only
- traffic-heavy but conversion-weak
- visibility proxies with no behavioral evidence

==================================================
DIVERSITY RULE
==================================================

Do not let the table become five near-duplicate rows from the same weak class.

Prefer a strong mix when supported by data, for example:
- one form-entry row
- one homepage/call-driver row
- one service-page row
- one FAQ/research row
- one staff/trust row

If the data supports that mix, prefer it over five generic GSC rows.

==================================================
NOTES / WHAT WE’RE LEARNING IMPROVEMENT
==================================================

Strengthen the note-generation logic so higher-confidence rows sound more definitive and lower-confidence rows sound appropriately cautious.

Examples:
- GA4 form-start row:
  “Strongest trackable on-site conversion path; users are demonstrating direct admissions intent here.”
- Call-tracking homepage row:
  “Primary call-driver and likely local-entry page; phone intent is concentrated here.”
- Service-page phone-click row:
  “One of the clearest non-homepage conversion paths; users are moving from service evaluation to action.”
- FAQ page row:
  “Pre-call evaluation behavior; users are validating fit before committing.”
- GSC fallback row:
  “High-visibility page with likely support value, but direct conversion attribution is limited.”

Do not let weak GSC rows sound stronger than GA4/CTM/CallRail rows.

==================================================
SOURCE BADGE RULES
==================================================

Keep the current source badge-on-Type approach, but improve badge priority:
- GA4 rows should show GA4
- call-tracking rows should show CallRail / CTM / Nimbata as appropriate
- multi-source rows can show multiple badges if that is real and useful
- GSC badge should appear only when the row is truly a fallback / proxy row

==================================================
TABLE FILL RULE
==================================================

If there are fewer than 5 strong rows:

- higher-confidence rows must always appear first
- fallback rows must appear later in the table
