GLOBAL NON-NEGOTIABLE RULES

1) TRUTHFULNESS RULE
The system must stop making unsupported claims about the website.
Do not say things like:
- missing from navigation
- not clearly accessible
- absent from site structure
- no hub exists
unless the crawl and report evidence actually prove it.

If something is present in the site menu, header, footer, page architecture, or page content, the report must not say it is missing.

If the system cannot verify something, it must clearly mark it as an inference.

2) FACT / INFERENCE / UNKNOWN RULE
All diagnostic language must fall into one of three states:
- Fact
- Inference
- Unknown

Formatting rules:
- Facts are stated plainly.
- Inferences must be prefixed with: “Inference:”
- Unknown states must be dismissed and not shown in the report.

Do not convert uncertainty into false certainty. Data is king.

3) SOURCE LABELING RULE
No data may appear anywhere in the report without showing the source integration or source set (website crawl, sitemap, etc) that produced it.

Use this exact logic:
- If the entire table uses the same integration(s), show the source label beside the table header.
- If rows within the table use different integrations, show the source on each row.
- Never leave data unlabeled.
- Never apply row-level labeling redundantly if the whole table is same-source.

Examples:
- If Top Converting Pages is all CallRail, show “CallRail” beside the table header.
- If What Matters Most has mixed GA4 and CallRail rows, show source on each row.

4) FRESH CRAWL RULE
The system must perform a fresh crawl every generation and interpret it thoroughly.

That crawl must inspect:
- main nav / header
- footer
- primary templates
- level of care pages
- service pages
- trust and eligibility pages
- verify insurance / VOB pages
- admissions/contact paths
- internal linking
- page layouts
- major structural blocks
- technical findings from crawl output

The system must read the technical report carefully enough to avoid contradicting visible site structure.

It must distinguish between:
- not found
- not indexed
- not prominent
- not verified

5) PRIORITY ACTION TRACEABILITY RULE
Every action in “What We Need to Do Next” must tie back to actual evidence from one or more of:
- crawl findings
- technical findings
- GA4 findings
- GSC findings
- CallRail findings
- page architecture findings
- AM notes / priority checks

No generic filler actions.
No vague “improve content” language unless tied to specific findings.
All issues found in other sections of the report must be addressed in “What We Need to Do Next”.

6) KEYWORD CLUSTERING RULE
Closely linked keyword variants with the same intent must be grouped into one row when appropriate.

Example:
- relapse definition
- definition of relapse
- relapse meaning

These should be grouped into a single keyword cluster row, not shown as three separate recommendations.

Important:
The grouped row may still list all three terms inside the Keyword field, but it must be one strategic recommendation row.

Additional hard rules:
- Max 1 row for any tightly linked semantic cluster unless materially different intent is proven.
- Remove low-fit intent recommendations that do not align with treatment-seeking behavior or stated strategy.
- The output must include a mix of:
  - New page needed
  - Content refresh
  - CRO update
  - Technical (Screaming Frog findings)
Unless AM Priority Checks explicitly say not to recommend new content this quarter.

7) HUB LANGUAGE RULE
If the system uses the term “hub,” it must explain it in plain language the first time it appears.

Use something like:
“A hub is a parent page that organizes related subtopics and helps users and search engines understand the relationship between those pages.”

If recommending a hub, the system must also prove why it is needed.

A hub recommendation may only appear if at least one of these is true:
- no qualifying parent page exists
- a parent page exists but is thin or non-strategic
- related child pages exist without coherent parent structure
- internal linking between related pages is weak or missing

Do not recommend a hub casually.
