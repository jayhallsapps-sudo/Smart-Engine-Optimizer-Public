Build the next Phase 2 bridge for SmartEO: findings-to-report-builder handoff.

IMPORTANT CONTEXT

The following already exist and must be extended, not replaced:
- guided workflow shell at /workflow
- stable finding object model
- contextual finding chat
- comments/review system
- report registry
- existing report builders/pages
- read mode / focus mode / presentation mode foundations
- client pre-seeding via URL params

Do not rebuild the workflow or report pages from scratch.

CORE OBJECTIVE

Reduce the disconnect between SmartEO’s guided workflow and the actual report builders by passing committed workflow decisions into the destination report page in a meaningful, structured way.

Right now the workflow can prepare thinking, but the report builder still requires too much re-entry. This prompt should begin closing that gap.

PRIMARY GOALS

1. PASS WORKFLOW OUTPUT FORWARD

At minimum, the handoff from /workflow into the destination report page should carry:
- selected client
- selected report type
- committed findings by strategy area
- AM inputs by strategy area where relevant

Do not overreach into a full final intelligence engine.
Do create a structured bridge that lets the report page know what the workflow produced.

2. CHOOSE THE LEAST RISKY HANDOFF MODEL

Use the least disruptive architecture that fits the current product state.

Acceptable approaches could include:
- lightweight persisted workflow session
- temporary saved draft object
- structured local persistence keyed by report/client/type
- another approach if it is cleaner and well justified

Avoid:
- huge URL payloads
- brittle one-off hacks
- rewriting every report page from scratch

3. MAKE THE REPORT PAGE AWARE OF INCOMING WORKFLOW CONTEXT

The destination report pages should be able to detect:
- whether they were launched from workflow
- what structured prep context is available
- what has already been decided/committed

For this phase, it is acceptable if the report builder:
- pre-populates selected fields
- shows a workflow summary panel
- gives the user a way to apply/import the workflow prep
- or uses another practical intermediary UX

The key requirement is that the workflow output no longer disappears into a dead end.

4. PRESERVE CURRENT REPORT BUILDER USABILITY

Requirements:
- power users should still be able to use report pages directly
- quick launch should still work
- existing save/load/report generation behavior must not break
- workflow-originated context should enhance the report builder, not trap it

5. KEEP IT REPORT-FAMILY AWARE

Requirements:
- deck-style and document-style reports may consume workflow prep differently later
- do not hardcode a one-size-fits-all ingestion model that blocks future report-family divergence
- build a shared structured handoff layer, with family-specific consumption able to come later

6. REUSE / COMPATIBILITY RULES

- reuse existing workflow state and finding model
- reuse existing report pages wherever possible
- reuse current client/report routing conventions where possible
- do not replace the current report generation system
- do not break saved reports
- do not overbuild admin/template systems in this prompt

7. DEFERRED ITEMS

Do not try to complete in this prompt:
- final AI-generated section writing
- full QBS → QBR auto-derivation
- final intelligence engine
- full workflow session history UI
- full approval system

This prompt is about the bridge, not the entire future system.

DELIVERABLES

Build/refine:
- structured workflow handoff model
- workflow-origin detection in report pages
- meaningful pre-population or import behavior in destination report pages
- preservation of direct-use report builder paths

IMPLEMENTATION REPORT REQUIRED

After building, provide a short implementation report including:
- files changed
- what was reused
- what was refactored
- what was newly added
- exact handoff model chosen
- what data now carries from workflow to report page
- what still does not carry over
- any UX compromises
- any risks or deferred items

SUCCESS CONDITION

A SmartEO user can complete guided workflow prep and arrive in the report builder with meaningful structured context already carried forward, reducing duplicate effort and making the workflow feel like a real part of report creation rather than a disconnected pre-step.
