The print route may hide app chrome, sidebars, buttons, and editing controls, but it must not use a different layout engine or different markup for the report body

Do not use PDFKit or any manual PDF drawing for the designed report

Do not create a second export template unless it is literally the same report component with print-only CSS

Puppeteer PDF requirements:

Use Puppeteer page.pdf()

Set printBackground: true

Set preferCSSPageSize: true

Set margin top/right/bottom/left to 0

Wait for document.fonts.ready before exporting

Wait for all images to load before exporting

If icons are SVG, ensure they are inline SVG or fully loaded before print

Emulate print media before export

Export only after the report container has finished rendering and layout is stable

Implement this exact export flow:

Open the print URL in Puppeteer

Wait until networkidle

Wait for the report root selector

Wait for document.fonts.ready

Wait one animation frame or short timeout after fonts resolve

Measure the report container height if needed

Call page.pdf with background graphics enabled and no added margins

Use this Puppeteer pattern:

await page.goto(printUrl, { waitUntil: 'networkidle0' });
await page.waitForSelector('[data-report-root]');
await page.emulateMediaType('print');

await page.evaluate(async () => {
  await document.fonts.ready;

  const imgs = Array.from(document.images);
  await Promise.all(
    imgs.map(img => {
      if (img.complete) return Promise.resolve();
      return new Promise(resolve => {
        img.addEventListener('load', resolve, { once: true });
        img.addEventListener('error', resolve, { once: true });
      });
    })
  );
});

CSS print requirements:

Add a dedicated print stylesheet

Use @page { size: Letter; margin: 0; }

Put the visual page padding inside the report page container, not in browser margins

Remove any accidental border, outline, or box-shadow on the outer page wrapper

Avoid transform: scale(), zoom, or CSS transforms on report/page wrappers

Avoid viewport-based sizing for print where possible

Use fixed widths in print for the report page, for example 8.5in wide with inner layout padding

Force header art to use absolute positioning relative to the page container, not viewport

Ensure overflow is visible unless intentionally clipped

Page break rules:

Split the report into explicit page sections

Each page should be a .report-page container

Use break-after: page on each page except the last

Use break-inside: avoid on tables, table rows, cards, and key content blocks

If a large table spans pages, repeat table headers and control row breaking
