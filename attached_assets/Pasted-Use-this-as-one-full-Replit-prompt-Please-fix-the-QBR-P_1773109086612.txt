Use this as one full Replit prompt:

Please fix the QBR Prep report generation and rendering logic to match the intended workflow and output.

Core issue: the report is currently exposing internal AM scaffolding as client-facing content. That is wrong. The AM inputs are supposed to guide the AI in the background, not appear as their own standalone section at the top of the report.

Required fixes

1. AM inputs must be background-only, not a visible report section

Current problem:
The report is rendering AM Inputs, Client Sentiment, AM’s Thoughts, and Priority Checks as their own area at the beginning of the QBR Prep report.

Correct behavior:
Those inputs should be used only as internal guidance for report generation.

Implementation rules:

* Do not render a standalone section called AM Inputs, Client Sentiment, AM’s Thoughts, or Priority Checks anywhere in the client-facing report.
* The generator should ingest those fields and use them to shape the final report narrative, priorities, recommendations, rationale, and tasks.
* If AM Thoughts or Priority Checks contain useful context, fold that context naturally into the relevant report sections.
* If the AI would already make the same point from the data alone, do not repeat it just because it appeared in AM inputs.
* If the AM adds a strong reason, concern, or framing point, use that reasoning inside the relevant recommendation or task justification.
* Treat AM inputs as hidden strategic inputs, not report content.

Desired outcome:
The final report should feel smarter and more contextual because of the AM inputs, but the client should never see the AM scaffolding itself.

2. Top Traffic Pages table layout needs to be cleaned up

Current problem:
The Insight column makes the row too long and ugly because it is trying to live beside the core metrics.

Correct behavior:
Keep the main page metrics in the first row, and place the insight below that row.

Implementation rules:

* Keep the standard top-row headers across the table for the page-level metrics.
* Remove Insight from that top header row.
* For each page entry, render:

  * Row 1: all standard metrics for that page
  * Row 2: a full-width insight row directly beneath it
* The second row should visually belong to the page above it.
* The label can be “Insight” at the start of the second row, or the row can just be styled as a sub-row beneath the page.
* The insight row should span the full table width.
* Exported PDF/output must preserve this stacked layout clearly and cleanly.
* The insight text should remain concise and useful, not bloated.

Desired outcome:
Readable table. Metrics first. Commentary second.

3. Remove Comment Out Status from “What We Track” for now

Current problem:
Comment Out Status should not be visible right now.

Implementation rules:

* Remove or comment out Comment Out Status from the What We Track section for now.
* Do not display it in preview or export.
* Do not break the underlying structure if it may be reintroduced later.

4. Rebuild Additional Opportunities completely

Current problem:
Additional Opportunities is currently wrong in both structure and logic. It is listing things that are not true opportunities and not true upsell/cross-sell ideas.

Correct behavior:
Additional Opportunities should contain only high-level, client-presentable, monetizable opportunities that go beyond the current strategy.

Implementation rules:

* Maximum of 5 opportunities.
* Minimum can be 0 if nothing credible exists.
* Each opportunity should contain only:

  * Number
  * Title
  * Description
* Remove Description, Source, and Service as separate columns/fields from the visible output.
* Do not include operational notes, internal QA notes, or vague recommendations.
* Do not include things like “prioritize accuracy over completeness” or any generic best-practice filler.
* Only include opportunities that could realistically be upsold or cross-sold.
* These should be tangible, strategic add-ons that could cost money or expand scope.

Valid examples of the type of thing this section should include:

* Paid Media
* Paid Retargeting
* CRO Sprint
* Landing Page Build
* Technical Cleanup Sprint
* Review Generation / GBP Expansion
* Call Tracking / Attribution Improvements
* Content Expansion Sprint
* Local SEO Expansion
* Conversion-Focused Dev Support

Generation rules:

* The ADR should be able to review these and decide if they are accurate and appropriate.
* Keep each item in plain English.
* Title should be short and client-friendly.
* Description should explain what it is and why it could help.
* Do not overcomplicate this section.
* Do not force 5 items if only 1 to 3 legitimate opportunities exist.
* If the recommendation is not monetizable or scope-expanding, it does not belong here.

Desired output format example:

1. Paid Retargeting
   Re-engage non-converting visitors after they leave the site to improve return traffic and increase conversion opportunities from existing demand.

2. CRO Sprint
   Run a focused conversion-rate optimization project on key admission pages to improve form starts, call clicks, and overall lead quality.

3. Technical Cleanup Sprint
   Address deeper site health and structural issues that may be limiting crawl efficiency, rankings, and conversion flow.

5) Keep report logic aligned with business outcomes, not filler

Use the report to support business growth logic rather than traffic-only commentary. Recommendations should tie back to things like lead quality, VOBs, calls, admits, conversion paths, trust signals, site usability, and revenue-supporting growth opportunities where applicable. That aligns with how the AM role and Webserv SEO philosophy are defined.  

6. Maintain a trusted-advisor tone in output structure

The report should be consultative, clear, and client-safe. It should not expose internal thought scaffolding, and it should not feel like raw AI notes were dumped into the final deliverable. That matches Webserv’s expectation-setting and advisor model.

A fix is complete only if all of the below are true:

* No standalone AM Inputs section appears anywhere in the QBR Prep report.
