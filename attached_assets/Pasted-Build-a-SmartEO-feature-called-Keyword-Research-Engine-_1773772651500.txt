Build a SmartEO feature called Keyword Research Engine.

Purpose:
Create an SOP-aligned keyword research tool that helps Webserv users discover, validate, score, organize, and export keyword opportunities for any client type. The tool must support behavioral health, local service businesses, hospitality, RV resorts, and other non-YMYL businesses. Do not assume all clients are recovery centers or regulated industries.

Core product philosophy:
This tool is not a generic keyword explorer. It is a guided research workflow that follows Webserv’s SEO philosophy:
- client business goals come first
- search intent and user need come before raw volume
- recommendations must be defensible, measurable, and explainable
- rankings are indicators; business outcomes matter more
- SEO decisions should support content, CRO, internal linking, and business growth
- YMYL logic should only apply when the client or page type actually requires it

Source logic to reflect:
- Webserv prioritizes impact over volume and aligns all SEO work to business outcomes
- keyword work should be grouped into clusters tied to business goals
- keyword opportunities should connect to conversions, lead quality, or revenue goals where applicable
- content and internal linking should reinforce topical authority and funnel intent
- SERP validation should review the top 3 non-Wikipedia results and identify major subtopics, trust elements, FAQs, and intent gaps
- monthly strategy references top keyword clusters, average position, impressions, and clicks, but this tool itself is a general research and planning engine, not a monthly report builder
- blog refresh and service page SOPs require Ahrefs Keyword Overview plus top SERP review before target selection

Primary feature goal:
Allow a user to run structured keyword research for a selected client/domain and generate a manually editable keyword research workspace with:
- keyword clusters
- keyword candidates
- business-goal relevance scoring
- SERP validation
- intent mapping
- recommended page type
- opportunity scoring
- content/internal-link implications
- exportable outputs

HIGH-LEVEL WORKFLOW

STEP 1: Business Goal Intake
Create a required intake step before any keyword generation begins.

Inputs:
- client name
- primary domain
- optional subfolder/subdomain scope
- business type
- industry category
- market type:
  - local
  - regional
  - national
  - multi-location
  - ecommerce
  - hospitality
  - healthcare/YMYL
  - other
- location targets
- primary services/products/offers
- secondary services/products/offers
- target audience(s)
- primary conversion goals
- North Star Metric / main business KPI
- seasonal or campaign priorities
- competitor domains
- notes / strategic context

Important logic:
- YMYL/regulated logic must not be globally assumed
- add a boolean or enum such as:
  - is_ymyl = true/false
  - compliance_sensitivity = low / medium / high
- if business type is healthcare, legal, finance, addiction treatment, medical, or similar, apply trust/compliance-enhanced rules
- if business type is non-YMYL, such as RV resort, restaurant, local service, tourism, ecommerce, etc., do not force YMYL-specific trust scoring

Output of Step 1:
A normalized client strategy profile object used by all downstream scoring.

STEP 2: Cluster Seeding
Generate keyword clusters using multiple inputs.

Data sources / mappings:
- Google Search Console:
  - existing queries
  - query impressions
  - clicks
  - average position
  - page associations
- Ahrefs or SEMrush:
  - keyword ideas
  - parent topic / related keywords
  - SERP overview
  - keyword difficulty
  - volume
  - traffic potential
- site architecture / crawl:
  - existing service pages
  - location pages
  - blogs
  - insurance pages
  - conversion pages
- optional manual competitor domains
- optional Screaming Frog upload if crawl-based page classification or title/H1 extraction is needed

Cluster types may include:
- service clusters
- location clusters
- problem/symptom clusters
- comparison clusters
- cost/pricing clusters
- insurance/payment clusters
- amenity/experience clusters
- branded and non-branded clusters
- FAQ / informational support clusters

Rules:
- cluster by business relevance first, not just tool similarity
- preserve relationship between head term and long-tail support terms
- identify whether each cluster is:
  - core revenue cluster
  - support / authority cluster
  - local visibility cluster
  - CRO support cluster
  - brand protection cluster

Output:
A list of clusters, each with:
- cluster name
- cluster type
- linked business goal
- primary candidate keywords
- secondary/supporting keywords
- current page coverage status

STEP 3: SERP + Intent Validation
For each proposed primary keyword and important secondary keyword, run validation.

Required logic:
- inspect the top 3 non-Wikipedia organic results
- inspect Ahrefs Keyword Overview or equivalent source
- identify:
  - dominant intent
  - mixed intent if applicable
  - common subtopics
  - FAQs/questions
  - trust signals shown on ranking pages
  - local pack presence
  - map pack presence
  - video/image/news presence if relevant
  - page type ranking most often
  - whether the SERP is dominated by directories, brands, blogs, service pages, category pages, or local pages

Intent categories:
- transactional
- commercial investigation
- informational
- navigational
- local intent
- mixed intent

Trust/compliance logic:
- if is_ymyl = true or compliance_sensitivity = high, include stronger checks for:
  - trust elements
  - credentials
  - disclaimers
  - evidence expectations
  - regulated language sensitivity
- if non-YMYL, trust checks can still exist, but should match the business type rather than healthcare-style compliance

Intent-gap logic:
Flag common missing intent angles such as:
- cost
- process
- who it is for
- amenities
- location specifics
- eligibility
- insurance
- risks
- comparisons
- FAQs
- booking/logistics
- what to expect
Only surface those that actually fit the business and SERP.

Output for each keyword:
- validated primary intent
- secondary intent
- best-fit page type
- SERP confidence score
- common subtopics
- notable SERP features
- notes on why this keyword is or is not viable

STEP 4: Opportunity Scoring
Score every keyword and every cluster.

Must include a dedicated Business Goal Alignment Score.

Required scoring fields:
1. Business Goal Alignment Score (0–10)
   Measures how directly the keyword supports the client’s stated business goals, primary offers, locations, and conversion priorities.

2. Intent Fit Score (0–10)
   Measures whether the SERP intent matches what the client can realistically satisfy.

3. Current Traction Score (0–10)
   Based on GSC visibility, existing rankings, impressions, clicks, and current page associations.

4. Ranking Opportunity Score (0–10)
   Based on difficulty, competition, SERP makeup, domain/page strength, and realistic rankability.

5. Conversion Proximity Score (0–10)
   Measures how close the keyword is to inquiry, booking, lead, sale, or other meaningful business action.

6. Topical Authority Value Score (0–10)
   Measures whether the keyword meaningfully strengthens an important cluster and internal-link ecosystem.

7. Content Effort Score (0–10)
   Measures effort required to produce a competitive asset.
   Important: lower effort can be better, but keep the raw number as effort burden.
   Also calculate an inverse “Ease Score” if useful.

8. Existing Coverage Score (0–10)
   Measures whether the domain already has a relevant page that can be refreshed, expanded, or repositioned.

9. Local Relevance Score (0–10)
   Only weight heavily when the business has local or geo-specific goals.

10. Trust/Compliance Complexity Score (0–10)
   Only relevant where appropriate. Higher means more care required.
   For non-YMYL clients this can remain low or optional.

Weighted final scores:
- Final Keyword Opportunity Score
- Final Cluster Priority Score

Default weighting guidance:
- Business Goal Alignment Score should be one of the heaviest weights
- Intent Fit Score should also be heavily weighted
- raw search volume should not dominate scoring
- if the business is local, local relevance should carry more weight
- if the business is YMYL/high-compliance, trust/compliance complexity should influence recommendation logic but not automatically suppress all opportunities

Allow admin-configurable weights.

STEP 5: Page-Type Recommendation Engine
For each keyword, assign a recommended target asset type.

Allowed page types:
- existing page refresh
- new blog
- new service page
- new location page
- new insurance/payment page
- FAQ page
- comparison page
- booking/amenity page
- category/hub page
- no action / not recommended

Recommendation logic should use:
- SERP intent
- existing page inventory
- business goals
- internal linking opportunities
- overlap/cannibalization risk

Also include:
- recommended primary URL target if an existing page is the best fit
- recommended new page title / slug concept if new content is needed
- cannibalization warning if multiple existing URLs already compete

STEP 6: Internal Linking + Topical Authority Suggestions
Because Webserv’s docs tie keyword and content opportunities to internal linking and topical authority, the tool must recommend link relationships.

For each approved keyword or cluster, suggest:
- best supporting service pages
- best supporting blogs
- best related location pages
- best conversion pages
- pages that should link to the proposed asset
- pages the proposed asset should link out to

Output:
- internal linking recommendations
- anchor text suggestions
- supporting cluster map
- indication of whether the asset strengthens a core cluster or sits too isolated to be a priority

STEP 7: Manual Editing Layer

Everything in the workspace must be manually editable by the user.

The user must be able to:
- edit cluster names

- edit intent labels
- edit page-type recommendations
- edit scores
- override page recommendations
- delete irrelevant keywords
- delete entire clusters
- add manual keywords
- add manual notes
- mark items as approved / rejected / watchlist
- lock rows from future auto-refresh
- duplicate keywords into another cluster if needed
- merge clusters
- split clusters

Important:
No AI-generated recommendation should be treated as final or immutable.

STEP 8: Saved Workspace + Versioning
Allow the user to save the research set as a project workspace.

Required save behavior:

- support rerun or refresh without wiping user edits

Refresh logic:
- new suggestions should enter as reviewable additions
- never overwrite user-edited values without explicit permission

BUSINESS GOAL ALIGNMENT SCORING LOGIC

Create explicit logic for Business Goal Alignment Score.

Score higher when:
- keyword directly matches a core service/product/offer
- keyword targets a priority location
- keyword aligns with the stated conversion goal
- keyword supports a high-priority funnel stage
- keyword supports a strategic initiative or seasonal campaign
- keyword has strong relevance to the client’s target audience

Score lower when:
- keyword is adjacent but not tied to a core offer
- keyword is purely informational with weak commercial connection
- keyword has weak geographic or offer relevance
- keyword may drive irrelevant traffic
- keyword reflects a service the client does not provide

Also allow manual override of this score.

RECOMMENDATION RULES

The system must never recommend a keyword just because it has volume.

Before recommending a keyword as priority, the system should be able to answer:
- what business goal does this support?
- what cluster does it belong to?
- what is the validated SERP intent?
- what page type should target it?
- does the client already have a page that can serve it?
- what makes this keyword realistically winnable or strategically useful?

If those cannot be answered, mark it as:
- low confidence
- review required
or
- not recommended

NON-YMYL VS YMYL RULES

Build conditional logic:
- If YMYL/high-compliance:
  - require stronger trust-element review
  - show compliance sensitivity
  - emphasize evidence, credibility, and page trust expectations
- If non-YMYL:
  - do not inject medical/legal/finance trust rules where they do not belong
  - still assess legitimacy and quality, but in a business-appropriate way

Examples:
- RV resort: amenities, booking/logistics, local intent, accommodations, reviews, experience, proximity, seasonal travel terms
- recovery center: treatment intent, service clarity, insurance, trust, compliance, E-E-A-T, conversion support
- local trades business: service + city intent, availability, service area, estimates, trust, reviews
- ecommerce: category intent, product modifiers, comparison, purchase readiness

GUARDRAILS

Do not:
- assume all clients are treatment centers
- over-prioritize volume
- overwrite manual edits
- force monthly reporting language into the tool
- make every keyword recommendation content-first if CRO/refresh is the better play
- recommend pages that contradict client business reality
- recommend keywords unsupported by search intent
- recommend YMYL-style trust structures for clearly non-YMYL clients

SUCCESS CRITERIA

This feature is successful if a user can:
1. select a client and define business goals
2. generate clusters and keyword opportunities
3. validate intent and SERP fit
4. see a strong business-goal alignment score
5. edit, remove, and approve keywords manually
6. understand what page type should target each opportunity
7. see how it connects to topical authority and internal linking
8. save the workspace without losing edits
9. export the final research set to PDF and XLSX

Build this feature in a way that feels like a SmartEO workflow, not a generic SEO tool.
