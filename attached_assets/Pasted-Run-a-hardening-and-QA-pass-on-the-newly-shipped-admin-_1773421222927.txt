Run a hardening and QA pass on the newly shipped admin auth + template builder systems.

IMPORTANT CONTEXT

These systems already exist and must be validated and tightened, not rebuilt:
- server-enforced admin write protection
- admin unlock flow in the sidebar
- admin config/template editing
- /admin/templates
- runtime template consumption in workflow assembly
- public read / protected write pattern

CORE OBJECTIVE

Find and fix any structural, UX, or consistency issues in the new admin auth and template-builder flows before adding more major features.

PRIORITY CHECKS

1. ADMIN AUTH HARDENING
- verify all admin write routes are protected consistently
- verify no write path is accidentally left open
- verify unauthorized failure handling is clean in the UI
- verify expired/cleared admin session behaves correctly
- verify no sensitive token value is exposed in logs, UI, or client state beyond what is necessary for the current session

2. TEMPLATE BUILDER QA
- verify all 4 report types behave correctly
- verify inline label edits persist and reload correctly
- verify visibility toggles persist and affect runtime correctly
- verify reorder logic is stable
- verify reset-to-default works reliably
- verify “custom” labeling appears only when appropriate
- verify fallback-to-code-default behavior is correct

3. RUNTIME CONSUMPTION QA
- verify workflow assembly reflects template overrides correctly
- verify disabled sections do not appear where they should not
- verify reordered sections render in the expected order
- verify no existing saved report behavior is broken by template overrides
- verify direct report-page usage still works

4. CONSISTENCY QA
- verify canonical report names are used everywhere
- verify QBS/QBR naming is still clean
- verify template UI does not expose unsafe editable keys
- verify read-only vs editable fields are visually clear

5. CLEANUP
- fix any low-risk inconsistencies or rough edges found during this pass
- do not overbuild new features
- document any deeper issues that should be deferred

DELIVERABLES

Provide:
- fixes for any issues found
- short QA report listing:
  - what was tested
  - what was fixed
  - what remains acceptable but deferred
  - any risks still worth watching

SUCCESS CONDITION

The admin auth and template-builder systems are stable, consistent, and safe enough that SmartEO can keep building on top of them without accumulating preventable structural debt.
