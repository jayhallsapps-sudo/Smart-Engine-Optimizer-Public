We need a full correction of the QBR Prep report flow, report logic, gap-question workflow, and modal UI. Right now the system is asking weak generic questions, pulling some key fields incorrectly, and presenting parts of the report in a way that does not match how the workflow is supposed to function.

Treat this as a proper product and logic fix, not a patch.

MAIN GOAL

The QBR Prep process should work like this:

1. Gather all available report inputs first:
- AM inputs
- client sentiment
- AM thoughts
- priority checks
- connected data sources
- NSM tracker data
- call tracking / GSC / GA4 / report source data already available
- QSSB + Notion context for client-facing strategic questions

2. Generate the best possible report from real data plus AM context.

3. Only if the user explicitly activates the gap workflow, evaluate what is missing and ask highly targeted follow-up questions.

4. Make the modal feel polished, modern, intentional, and actually pleasant to use.

==================================================
1) GAP-QUESTION LOGIC MUST BE USER-ACTIVATED ONLY
==================================================

This must be explicit and hard-coded.

Correct behavior:
- Do not auto-run gap analysis
- Do not auto-generate follow-up questions during normal report generation
- Do not interrupt report generation with questions unless the user explicitly activates the gap / fill-in-the-gaps workflow

Default behavior:
- no questions asked
- no question UI shown
- no missing-data interrogation
- no speculative prompts
- report still generates using the best available inputs

Only when the user explicitly activates a gap-related action should the system run gap logic.

Examples of valid manual triggers:
- Fill Gaps
- Find Missing Inputs
- Improve Report Accuracy
- Resolve Missing Data
- or any equivalent clearly intentional user action

If the trigger is NOT activated:
- ask zero questions
- show zero question cards
- do not block report generation
- do not inject generic missing-info prompts
- do not run a visible or invisible question workflow in the background

If the trigger IS activated:
- analyze the already-generated report and supporting inputs
- identify actual holes that materially affect report quality or accuracy
- ask only targeted, account-specific follow-up questions

Gap questions are optional workflow support, not a mandatory step in report creation.

2) REDESIGN THE GAP-QUESTION LOGIC COMPLETELY
==================================================

Current problem:
When the gap flow is used, the modal is asking bad, generic filler questions. Most of them should never be asked. Example of a bad question:
- “Do you have the connections to be able to do this work?”

That is useless, generic, and not tied to a real reporting gap.

Correct behavior:
Gap questions should only appear when the system cannot complete a specific field, recommendation, rationale, or report section with confidence.

New rules for question generation:
- Never ask broad generic questions
- Never ask obvious internal-capability questions
- Never ask vague questions that could apply to any account
- Every question must be tied to a specific missing field, unclear data point, contradiction, or missing context in the actual report
- Questions should be generated only after the system attempts full report assembly
- Questions should be specific, pointed, and useful enough that the answer clearly improves a report section

Good question behavior examples:
- If client sentiment is marked “frustrated,” asking “Why is the client frustrated?” is valid
- If the primary goal metric is missing its actual target number, ask a question specifically about that target only if it truly cannot be read from the connected source
- If a recommendation depends on a known blocker but the blocker is unclear, ask exactly what is unclear

Question generation order:
1. Try to resolve from structured data
2. Try to resolve from AM inputs / thoughts / priority checks
3. Try to resolve from prior report context / connected systems
4. Only then ask a human follow-up question

Each generated question must include hidden internal metadata:
- missingField
- sectionName
- whyThisMatters
- confidenceScore
- suggestedAnswerType

Allowed question types:
- clarification
- missing number
- missing goal target
- client context
- priority confirmation
- relationship risk
- dependency / blocker
- strategic direction

Question UX requirements:
- maximum 5 questions shown at once
- rank by importance
- show the most report-blocking questions first
- group similar questions together when possible
- remove repetitive wording
- every question should feel account-specific

Hard validation rule:
If a generated question could be reused word-for-word on most accounts, reject it and regenerate it.
