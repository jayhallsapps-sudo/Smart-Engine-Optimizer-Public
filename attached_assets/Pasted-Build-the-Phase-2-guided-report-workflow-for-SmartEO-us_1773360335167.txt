Build the Phase 2 guided report workflow for SmartEO using a stepper-style experience.

IMPORTANT CONTEXT

The following Phase 2 foundations are already in place and must be extended, not replaced:
- Phase 2 foundation / reuse-first architecture
- Command Center
- canonical report registry
- report family split foundations
- repurposed left sidebar as a secondary user/account/admin context panel

Use as much of the existing report creation, report page, preview, registry, and generation infrastructure as possible. Reuse first. Refactor only where necessary. Replace only with a clear documented reason.

Do not casually rewrite working report flows.

CORE OBJECTIVE

Create a stepper-based guided workflow for report preparation that feels controlled, screen-contained, and non-overwhelming.

This should be the beginning of SmartEO’s real guided strategy workspace.

CRITICAL UX RULES

- Avoid long endless forms and giant scrolling pages.
- Each step should feel focused and mostly fit within the visible screen.
- Use clear Next and Back navigation.
- The workflow should feel guided, not like a cluttered dashboard or admin form.
- Keep the interface calm, modern, and desktop-first.
- Reduce cognitive load.
- Preserve compatibility with the existing QBS design language where relevant.

TOP-LEVEL WORKFLOW

Build the report preparation flow as a stepper with these top-level steps:

- Step 1: Select Report Type
- Step 2: Select Client
- Step 3: AM Inputs / Strategy Areas
- Step 4: Findings Review
- Step 5: Report Assembly
- Step 6: Preview / Edit
- Step 7: Save / Export / Present

Within strategy areas, support a nested mini-flow where appropriate:

- Input
- Analysis
- Questions
- Findings
- Commit

CORE STRATEGY SECTIONS

The workflow must be able to support these strategy areas:

- Content Refresh
- New Content
- CRO Content
- Technical Infrastructure
- Technical Content
- Advanced Technical
- Local / GBP / Location
- Discoverability Layer / AI retrieval considerations

REQUIREMENTS FOR EACH STRATEGY AREA

Per section, the workflow should support:

- ask for AM input first
- allow the AM to provide observations/context
- show a live processing/analyzing state
- allow follow-up questions if needed
- return findings/recommendations
- allow the user to select what should be included
- allow revisions before committing
- allow clear next/back navigation
- keep the experience visually contained and not overwhelming

IMPORTANT IMPLEMENTATION APPROACH

Do not try to fully implement the final intelligence engine in this prompt.

For this phase:
- build the workflow shell
- build the interaction model
- build realistic analysis/loading/question/findings states
- use realistic placeholder/mock states where deeper analysis logic is not yet ready
- preserve compatibility with both report families
- preserve compatibility with existing report pages and preview flows

Do not overbuild:
- comments
- presentation mode
- final admin routing controls
- final template system
in this prompt

Those come later.

REPORT-AWARENESS RULES

The workflow must respect the canonical report definitions already established:

- Kickoff Deck
- Mid-Strategy Deck
- Launch Deck
- Bi-Weekly Report
- Monthly Report
- QBS
- QBR

- QBS is internal only
- QBR is client-facing
- QBR is downstream from QBS
- slideshow-style and document-style reports may diverge later inside the workflow
- do not hardcode a one-size-fits-all experience that blocks later family-specific behavior

REUSE / COMPATIBILITY RULES

- reuse existing report selection and routing where practical
- reuse existing generation and preview logic where practical
- do not break current report pages
- do not replace working report logic without reason
- preserve current saved report behavior
- be mindful of the pre-existing mid_strategy vs mid_strategy_seo mismatch as a known cleanup item, but do not create new inconsistencies

DESIGN / UX REQUIREMENTS

- stepper-based layout
- mostly screen-contained steps
- clear hierarchy
- low clutter
- professional SaaS feel
- the workflow should feel like moving through a controlled internal process
- no giant scroll-heavy report-builder pages

DELIVERABLES

Build:
- stepper-based workflow shell
- entry from Prepare a Report into the guided flow
- strategy area step screens
- nested section mini-flow where appropriate
- realistic analysis/loading/question/findings states
- movement into report assembly and preview flow
- support for both report families at the workflow level
