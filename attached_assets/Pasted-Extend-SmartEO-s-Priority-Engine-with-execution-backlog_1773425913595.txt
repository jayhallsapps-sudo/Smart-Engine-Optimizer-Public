Extend SmartEO’s Priority Engine with execution/backlog awareness so findings can be ranked with some understanding of whether related work is already planned, in progress, completed, or repeatedly deferred.

IMPORTANT CONTEXT

The following already exist and must be extended, not replaced:
- guided workflow shell
- stable finding object model
- heuristic priority engine
- manual priority overrides
- workflow session persistence
- workflow-to-report handoff
- current Airtable / Asana integration layer foundations
- admin guidance/config systems

Do not rebuild the workflow or priority engine from scratch.

CORE OBJECTIVE

Make priority ranking more practically useful by incorporating lightweight execution awareness, so SmartEO can distinguish between:
- urgent work not yet planned
- work already in progress
- work that has been deferred repeatedly
- work that may not need to be re-prioritized because it is already accounted for

PRIMARY GOALS

1. DEFINE A FIRST EXECUTION SIGNAL MODEL

Create a lightweight execution-awareness layer for findings.

Start with practical statuses such as:
- not tracked
- proposed
- planned
- in progress
- blocked
- completed
- deferred

Do not overbuild a full task engine in this prompt.

2. CONNECT FINDINGS TO EXECUTION CONTEXT

Use the lightest sensible approach to associate findings with execution context.

Acceptable early approaches:
- manual AM tagging/linking from within workflow
- lightweight matching against existing task/backlog concepts
- a small intermediate execution status model

Do not assume perfect automated mapping yet.

3. ADJUST PRIORITY DISPLAY WITH EXECUTION AWARENESS

Requirements:
- priority display should reflect execution context in a clear but restrained way
- a finding already in progress should not look identical to an untouched finding
- a repeatedly deferred or blocked item should surface differently from a brand-new suggestion
- keep the UI calm and useful

4. PRESERVE HUMAN CONTROL

Requirements:
- execution awareness should inform the AM, not auto-hide work
- AM should still be able to select/reject/override findings
- do not let execution context silently suppress important findings without visibility

5. PREPARE FOR FUTURE INTEGRATIONS

Structure this so later it can connect more deeply to:
- Airtable backlog items
- Asana tasks
- completion status
- due dates
- ownership
- recurring deferral patterns

Do not try to solve the full execution engine in this prompt.

6. REUSE / COMPATIBILITY RULES

- preserve the current finding model and priority engine
- preserve manual priority override behavior
- preserve workflow session persistence
- do not break workflow-to-report mapping or report pages
- extend rather than replace

7. DEFERRED ITEMS

Do not build in this prompt:
- full Airtable/Asana sync intelligence
- automatic task creation
- final cross-period strategy memory
- full execution analytics dashboard
- final account-level recommendation memory

This prompt is about the first execution-aware priority layer, not the full strategic memory system.

DELIVERABLES

Build/refine:
- first execution status model
- finding-level execution awareness
- priority display improvements informed by execution state
- lightweight workflow UI for viewing/setting execution state where appropriate

IMPLEMENTATION REPORT REQUIRED

After building, provide a short implementation report including:
- files changed
- what was reused
- what was refactored
- what was newly added
- exact execution status model
- how execution state affects priority display/ranking
- what remains manual or heuristic
- any UX compromises
- any risks or deferred items

SUCCESS CONDITION

A SmartEO user reviewing findings can see whether a recommendation is untouched, already planned, in progress, blocked, deferred, or completed, and that context helps make priority ranking more practically useful without breaking existing workflow control.
