Extend SmartEO’s execution-aware priority layer by connecting finding execution context to real Airtable / Asana references in a lightweight, non-destructive way.

IMPORTANT CONTEXT

The following already exist and must be extended, not replaced:
- guided workflow shell
- stable finding object model
- heuristic priority engine
- manual priority overrides
- executionContext on findings
- Finding Chat Panel execution controls
- workflow session persistence
- current Airtable / Asana integration foundations

Do not rebuild the workflow or priority engine from scratch.

CORE OBJECTIVE

Make execution context more useful by letting AMs connect findings to real Airtable/Asana work references and by adding lightweight validation or lookup behavior where practical.

PRIMARY GOALS

1. UPGRADE linkedRef FROM FREE TEXT TOWARD REAL REFERENCES

Requirements:
- preserve the current simple linkedRef concept
- improve it so AMs can more reliably connect a finding to a real work item
- do not overbuild a full task-management interface

Acceptable approaches:
- lightweight search/lookup for existing Airtable/Asana items
- structured reference picker
- validation against known task IDs or titles
- a hybrid approach if cleaner

2. IMPROVE EXECUTION CONFIDENCE

Requirements:
- make it clearer whether a finding is:
  - manually tagged only
  - linked to a real task/reference
- distinguish soft/manual execution state from task-linked execution state where practical

3. KEEP UX LIGHTWEIGHT

Requirements:
- keep the execution controls inside the current chat panel or another similarly low-clutter surface
- do not dump giant task pickers into the workflow
- make linking feel fast and practical for AMs

4. PREPARE FOR FUTURE DEEPER INTEGRATION

Structure this so it can later support:
- live task status
- ownership
- due dates
- automatic status suggestions
- richer backlog awareness

Do not build the full sync intelligence yet.

5. PRESERVE CURRENT CONTROL

Requirements:
- AM can still manually set execution status without linking a task
- linking should improve the context, not become mandatory
- do not break current priority, override, or session behavior

6. REUSE / COMPATIBILITY RULES

- preserve the current Finding / executionContext model where practical
- preserve workflow session persistence
- preserve current chat panel structure
- extend the current integration layer rather than inventing a separate execution system

7. DEFERRED ITEMS

Do not build in this prompt:
- full automatic task creation
- final Airtable/Asana sync intelligence
- complete execution analytics dashboard
- account-level recurring finding memory
- final recommendation-to-task automation

This prompt is about making execution references more real and useful, not solving the whole execution engine.

DELIVERABLES

Build/refine:
- improved execution reference model
- lightweight Airtable/Asana reference linking or validation
- clearer display of linked vs unlinked execution context
- preserved manual fallback path

IMPLEMENTATION REPORT REQUIRED

After building, provide a short implementation report including:
- files changed
- what was reused
- what was refactored
- what was newly added
- exact linked-reference model now used
- how Airtable/Asana linking or validation works
- what remains manual
- any UX compromises
- any risks or deferred items

SUCCESS CONDITION

A SmartEO user can connect a finding’s execution context to a real Airtable or Asana work reference in a lightweight, useful way, making execution-aware prioritization more grounded without overcomplicating the workflow.
