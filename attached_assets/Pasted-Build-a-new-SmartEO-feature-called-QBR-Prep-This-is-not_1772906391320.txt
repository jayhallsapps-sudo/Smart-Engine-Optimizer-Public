Build a new SmartEO feature called QBR Prep.

This is not a chat wizard. This is a report generator inside the existing SmartEO app.

The output must be a polished, branded, inline-editable quarterly SEO planning report for behavioral health treatment center websites. It must inherit the Monthly report design system and export behavior, but use the content structure of the QBR Prep / SEO Planning Snapshot workflow.

Use this spec as the source of truth. Do not invent product behavior outside this spec. Do not redesign the report. Do not create a markdown artifact workflow. Do not build a content calendar or backlog tool.

==================================================
PRIMARY GOAL
==================================================

Implement QBR Prep as a SmartEO-generated quarterly planning report that:

1. uses the same visual language as the Monthly report
2. renders as a continuous-page live preview in the app
3. exports via the existing Monthly report export pipeline to:
   - PDF
   - DOCX
   - Google Drive
4. requires a fresh Screaming Frog crawl upload before generation
5. allows full inline editing after generation
6. autosaves and also supports manual save
7. persists a durable saved report state in the database
8. generates a 7-section quarterly planning snapshot for behavioral health treatment center websites
9. uses data from connected integrations with strong fallbacks
10. never invents missing data; instead render “Manual entry needed”

==================================================
NON-GOALS
==================================================

Do NOT build any of the following:

- a step-by-step Claude-style chat wizard
- a markdown artifact workflow
- a page-by-page content plan
- a keyword map
- a full six-month website roadmap
- endless recommendations
- a new export engine separate from Monthly unless absolutely required for reuse

==================================================
EXISTING PRODUCT CONTEXT
==================================================

SmartEO already has:
- client name
- domain
- connected integrations
- query_logs storing raw query results
- sf_reports / call_tracking_reports storing uploaded data
- printCache for temporary preview/printing
- a working Monthly report visual shell and export flow

Current behavior that matters:
- final generated files are NOT durably stored in the app today
- printCache is temporary and expires
- raw query results are durable
- uploaded Screaming Frog and manual call-tracking CSV data are durable

QBR Prep must add durable saved report state instead of relying only on printCache.

==================================================
QUARTER LOGIC
==================================================

Use standard business quarters:

- Q1 = Jan 1 to Mar 31
- Q2 = Apr 1 to Jun 30
- Q3 = Jul 1 to Sep 30
- Q4 = Oct 1 to Dec 31

Generation logic:
- analyze the current quarter to date using the generation date
- plan for the NEXT quarter

Example:
- generation date = 2026-03-07
- analysis window = 2026-01-01 through 2026-03-07
- planning quarter = Q2 2026

Comparison logic:
- upcoming quarter goals must be compared against prior quarter GOALS, not prior quarter ACTUALS
- recommended next-quarter goals should be generated from data and site condition
- goals do not automatically need to increase or decrease
- goals must be realistic and defensible

- Secondary Goal

Supporting context:
- GA4 quarter-to-date organic sessions
- call tracking quarter-to-date organic calls

- do not assume the next-quarter goal must be higher

- if insufficient, render manual-entry-needed state for the goal row

==================================================
SECTION 5
SEO TIER DIAGNOSIS
==================================================

Purpose:
Identify the current limiting tier using the Treatment Center SEO Priority Framework.

Output format:
- short analytical text block
- not a table
- concise but specific

Use a rule-based model, not generic AI opinion.

Tier 1 — Trust & Eligibility
Diagnose Tier 1 blocked when any of these are true:
- core service pages are missing, weak, ambiguous, duplicated, or cannibalized
- access-to-care pages are weak, unclear, or hard to reach
- admissions pathway is indirect or misleading
- high-intent service traffic does not land on clear primary URLs

Tier 2 — Structural Authority
Diagnose Tier 2 blocked when:
- Tier 1 is mostly sound
- site lacks strong conditions / therapies / location hub structure
- internal architecture is disorganized
- authority cannot flow cleanly

Tier 3 — Consolidation & Cleanup
Diagnose Tier 3 blocked when:
- tiers 1 and 2 are mostly sound
- legacy duplication, thin archives, overlapping geo/service pages, taxonomy clutter, or structural drag suppresses growth

Tier 4 — Conversion & Differentiation
Diagnose Tier 4 blocked when:
- tiers 1 to 3 are mostly healthy
- comparison-stage pages like About, leadership, team, aftercare, alumni, or credibility layers are limiting choice

Tier 5 — Expansion & Demand Capture
Diagnose Tier 5 blocked when:
- tiers 1 to 4 are mostly healthy
- main opportunity is informational expansion via blogs / FAQs / demand capture

Framework guardrails:
- never recommend Tier 4 or 5 before 1 and 2 are addressed
- Tier 1 refreshes outrank blog work
- cleanup outranks expansion
- diagnosis must cite observed evidence from crawl, conversion paths, and traffic patterns
