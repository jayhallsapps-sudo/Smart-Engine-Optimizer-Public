Build the first real Admin / Governance layer for SmartEO so leadership can control report structure and guidance inside the app instead of relying on hardcoded behavior.

IMPORTANT CONTEXT

The operational workflow spine of SmartEO already exists and must be extended, not replaced.

Existing foundation includes:
- Command Center
- report registry
- document-style and slideshow-style report family foundations
- workflow shell
- comments/review system
- contextual finding chat
- workflow-to-report field mapping
- QBS → QBR mapping
- quarter-aware QBS selection
- current report pages and save/load infrastructure

Do not rebuild the product from scratch.

CORE OBJECTIVE

Start the Admin / Governance layer so ADRs, the Director of SEO, and Owners can manage the logic that shapes reports and report preparation inside SmartEO.

This is not the full final admin system.
This is the first controlled layer that moves SmartEO away from “code-only configuration.”

PRIMARY GOALS

1. IN-APP ADMIN ACCESS

Build admin access inside the existing app shell, not as a separate external dashboard.

Requirements:
- admin users should be able to reach admin tools from inside SmartEO
- preserve the current app-shell/sidebar principle
- keep the experience clean and role-aware
- do not overbuild final auth in this prompt

2. TEMPLATE / CONFIG FOUNDATION

Build the first practical layer for managing report structure/config without hardcoding everything in code.

Start with one or both of the following, whichever fits the current architecture best:
- report template/config metadata editor
- report mapping/config viewer/editor

At minimum, leadership should be able to inspect and begin controlling:
- report type definitions
- report family labels
- field mapping rules
- source/use notes
- section/config metadata

Do not overbuild a giant WYSIWYG editor yet unless the foundation already strongly supports it.

3. INSTRUCTION / GUIDANCE FOUNDATION

Build the beginning of an admin-managed instruction layer.

At minimum, support:
- creating and editing internal guidance entries
- tagging them by report type and/or workflow area
- storing title + body + status + updated timestamp
- viewing them in a clean admin UI

This is the first step toward the future instruction-library vision.
Keep it lightweight and useful.

4. GOVERNANCE UX

Requirements:
- calm, professional internal admin UI
- not cluttered
- desktop-first
- feels like governance/configuration, not a public CMS
- should fit inside SmartEO’s existing design language

5. REUSE / COMPATIBILITY RULES

- reuse existing app shell and role-aware UI where possible
- do not break current report generation flows
- do not replace current registry/mapping logic unnecessarily
- where practical, surface existing config/code-driven structures in admin-friendly ways rather than rewriting everything immediately

6. PHASE LIMITS

Do not build in this prompt:
- full final auth/permissions enforcement
- full WYSIWYG template builder
- full document upload/processing pipeline
- complete source-routing manager
- final rules engine
- final enterprise admin console

This prompt is about creating the first useful admin/governance layer, not the entire finished admin platform.

DELIVERABLES

Build/refine:
- in-app admin entry point
- initial admin/governance pages
- editable/viewable report config foundation
- editable/viewable instruction/guidance foundation
- lightweight persistence if needed and appropriate

IMPLEMENTATION REPORT REQUIRED

After building, provide a short implementation report including:
- files changed
- what was reused
- what was refactored
- what was newly added
- what admin/config objects are now editable vs still code-only
- any UX compromises
- any risks or deferred items

SUCCESS CONDITION

A SmartEO admin user can enter an in-app governance area and begin viewing/editing the key report guidance/config foundations that shape how SmartEO behaves, making the product less dependent on hardcoded logic and more ready for leadership control.
