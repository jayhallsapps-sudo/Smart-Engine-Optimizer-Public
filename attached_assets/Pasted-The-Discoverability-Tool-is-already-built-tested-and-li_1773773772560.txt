PHASE B — RECOMMENDATION QUALITY
========================================

B1. Add Cannibalization Detection
The current implementation needs stronger cannibalization handling.

For every recommended keyword/page pair:
- inspect existing mapped URLs
- identify when multiple existing URLs appear to target the same or very similar intent
- flag potential cannibalization risk
- show severity:
  - low
  - medium
  - high

UI requirements:
- display warning in keyword detail drawer
- display warning in page recommendation card/table if relevant

Recommendation requirements:
For cannibalization cases, the system should suggest one of:
- consolidate into existing page A
- refresh existing page B
- merge/redirect candidate pages
- no new page recommended
- review manually

Do not create aggressive redirect recommendations without confidence. Default to advisory language.

B2. Tighten Page-Type Recommendation Logic
Improve recommendation quality so page types are not merely plausible but defensible.

Page-type recommendations must weigh:
- validated SERP intent
- business goal alignment
- current site inventory
- local relevance
- conversion proximity
- cannibalization risk
- whether an existing page can be refreshed instead of creating a new page

Allowed page types remain:
- existing page refresh
- new blog
- new service page
- new location page
- new insurance/payment page
- FAQ page
- comparison page
- booking/amenity page
- category/hub page
- no action / not recommended

Requirements:
- every recommendation must have a clear reason string
- reason string should be human-readable and concise
- example:
  “Informational SERP with existing partial coverage; best fit is a blog refresh supporting the detox cluster.”
- if confidence is weak, label as low confidence / review required

B3. Strengthen Business Goal Alignment Explainability
The score exists, but users need to trust it.

Add an explanation layer for Business Goal Alignment Score:
- show the key factors that increased the score
- show the key factors that lowered the score
- explicitly compare keyword relevance to:
  - primary services/offers
  - target locations
  - stated conversion goals
  - target audience
  - seasonal or strategic priorities

UI requirements:
- quick explanation in detail drawer
- optional tooltip or expandable rationale

Example format:
High because:
- directly matches a core service
- targets a priority location
- supports booking intent

Lower because:
- weak alignment with stated audience
- low connection to current conversion goal

B4. Improve Internal Linking Recommendations
The graph exists, but strengthen strategic usefulness.

Requirements:
- suggestions should not be generic
- anchor text suggestions should reflect keyword intent and target page relationship
- identify whether suggested links are:
  - cluster support
  - conversion support
  - authority reinforcement
  - local relevance support
- avoid recommending isolated pages with weak cluster support unless strategically justified

Add a short rationale for each internal link suggestion:
- why source page should link to target
- what role the link plays
