In server/claudeService.ts, refactor runAcaChat so it tries up to three providers in order:

1. Claude (Anthropic) — using @anthropic-ai/sdk, which is already installed. Use the ANTHROPIC_API_KEY secret. Model: use env var ANTHROPIC_MODEL or default "claude-sonnet-4-20250514". This is the existing implementation.

2. Grok (xAI) — using the existing XAI_API_KEY secret that's already configured. Grok's API is OpenAI-compatible. Use the openai npm package with baseURL "https://api.x.ai/v1" and the XAI_API_KEY. Model: "grok-3-latest" (or env var GROK_MODEL).

3. OpenAI — using the OPENAI_API_KEY secret. Use the openai npm package (install it: npm install openai). Model: "gpt-4o" (or env var OPENAI_MODEL).

The fallback logic should work like this:
- Try Claude first. If it fails (API key missing, auth error, rate limit, any error), log the error and fall through to Grok.
- Try Grok second. If it fails, log and fall through to OpenAI.
- Try OpenAI third. If it fails, throw the error to the caller.
- Log which provider was used: console.log("[ACA] Using provider: claude|grok|openai")

IMPORTANT for Grok and OpenAI: They don't support Anthropic's tool_use format. For these providers, instead of passing tools and doing a tool-use loop, do this:
- Before calling the model, pre-fetch the data from the selected integrations (see Part 2 — the request will include which integrations the user selected).
- Inject the fetched data directly into the system prompt as a JSON block under a "DATA CONTEXT" section.
- Then make a single chat completion call with no tools — just the system prompt (with data baked in) and the user messages.
- This is key for token savings too — we only fetch what the user explicitly asked for.
