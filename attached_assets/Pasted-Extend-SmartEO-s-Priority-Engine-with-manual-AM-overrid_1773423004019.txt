Extend SmartEO’s Priority Engine with manual AM override controls so users can adjust heuristic priority signals without losing the system-generated ranking.

IMPORTANT CONTEXT

The first Priority Engine layer already exists and must be extended, not replaced.

What already exists:
- finding-level priority metadata
- heuristic scoring based on impact / urgency / effort
- area defaults
- regex text-signal adjustments
- priority badges in workflow and finding chat
- current finding selection / status / revision flow

Do not rebuild the priority engine from scratch.

CORE OBJECTIVE

Let the AM explicitly override the heuristic priority signal in a clean, trackable way so SmartEO remains helpful without pretending the automatic ranking is always right.

PRIMARY GOALS

1. ADD MANUAL PRIORITY OVERRIDE CAPABILITY

Allow the AM to do actions such as:
- pin higher / boost priority
- lower priority
- suppress/deprioritize
- clear manual override and return to heuristic score

Use a practical, low-clutter UI.

2. PRESERVE BOTH LAYERS OF TRUTH

Requirements:
- keep the original heuristic priority
- store the manual override separately
- make it clear when a displayed priority is system-generated versus manually overridden
- do not destroy the original score/rationale when overridden

3. KEEP UX CALM AND EXPLAINABLE

Requirements:
- the override controls should feel lightweight and internal
- avoid cluttering every card with too many buttons
- if practical, place controls in the finding chat panel and/or an overflow menu
- show a clear visual indicator when a finding is manually overridden

4. INTEGRATE WITH WORKFLOW REVIEW

Requirements:
- overridden priority should appear consistently in:
  - findings phase
  - findings review step
  - finding chat panel
- sorting behavior should respect the effective displayed priority
- do not break current revision / accept / reject flow

5. PREPARE FOR FUTURE GOVERNANCE

Structure the data so later the system could support:
- admin-defined priority rules
- AM rationale notes for overrides
- reporting on override frequency
- account-level strategy memory

Do not build those future systems yet.

6. REUSE / COMPATIBILITY RULES

- preserve the current heuristic priority engine
- preserve current finding model where practical
- extend rather than replace
- do not break workflow-to-report handoff
- do not overbuild the final intelligence system

7. DEFERRED ITEMS

Do not build in this prompt:
- full historical priority memory
- backlog-aware reprioritization
- admin tuning UI for weights
- automatic task generation
- final explainability dashboard

This prompt is about AM control over priority, not the whole future scoring stack.

DELIVERABLES

Build/refine:
- manual priority override model
- lightweight override UI
- consistent display of effective priority vs heuristic priority
- sorting behavior using the effective priority

IMPLEMENTATION REPORT REQUIRED

After building, provide a short implementation report including:
- files changed
- what was reused
- what was refactored
- what was newly added
- exact override model
- where override controls appear
- how display and sorting now work
- any UX compromises
- any risks or deferred items

SUCCESS CONDITION

A SmartEO user can see the system-generated priority, override it when needed, and still preserve a clear distinction between heuristic priority and human-adjusted priority throughout the workflow.
