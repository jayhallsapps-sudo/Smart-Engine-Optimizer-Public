Fix how AM inputs are used across the reports.

Problem:
The AM inputs, especially:
- Client Sentiment / Hypothesis / Focus Area
- Manual Audit Notes

are currently being dumped into one big lump of text in a single explanation/note area.

That is wrong.

These inputs are supposed to:
1. give the generator context
2. shape interpretation throughout the report
3. support justification in the relevant sections
4. appear only where contextually appropriate
5. never appear as one pasted block of text unless a report explicitly has a dedicated AM notes section

==================================================
GOAL
==================================================

Refactor AM input handling so the inputs are distributed intelligently across the report, not dumped as a single blob.

The AM inputs should function as contextual signals, not as one visible memo.

==================================================
CORE RULE
==================================================

Treat AM inputs as structured context that influences report generation across multiple sections.

Do NOT:
- dump the raw AM inputs into one cell
- concatenate multiple AM inputs into one paragraph
- repeat the AM inputs verbatim across sections
- expose internal planning text in a clumsy way

Do:
- map each AM input to the sections where it is most relevant
- use the AM input to sharpen analysis and justification
- translate it into client-ready wording where needed
- omit it from sections where it adds no value

==================================================
AM INPUTS TO HANDLE
==================================================

At minimum, handle:
- Client Sentiment / Hypothesis / Focus Area
- Manual Audit Notes

If the report also includes other AM inputs, keep the same principle.

==================================================
DISTRIBUTION RULES
==================================================

Use these inputs across the report in contextually appropriate places.

Examples of correct usage:

Client Sentiment / Hypothesis / Focus Area
- should influence:
  - challenge framing
  - opportunity framing
  - next steps
  - strategy / priorities sections
  - “what we need to do next”
  - roadmap / alignment sections
- should NOT appear as one raw paragraph unless there is a dedicated strategy commentary block designed for it

Manual Audit Notes
- should influence:
  - technical observations
  - structural gaps
  - service page issues
  - crawl-based recommendations
  - risk flags
  - page cleanup / cannibalization logic
  - tactical recommendations
- should NOT appear as one giant pasted text block

==================================================
HOW TO USE THEM
==================================================

Refactor the report generator so AM inputs are:
- parsed as structured context
- attached to interpretation steps
- selectively injected into the relevant rows / bullets / notes / commentary blocks

Examples:
- if hypothesis says “focus on service-page trust and admissions path”
  that should shape:
  - challenge slide
  - next-quarter tactics
  - recommendations
  - notes in relevant tables

- if manual audit notes mention:
  - missing metadata
  - weak internal linking
  - cannibalization
  - poor admissions path
  those should appear in:
  - technical observations
  - risk sections
  - what’s next
  - site service / cleanup / priority notes
not as a pasted memo block

==================================================
IMPLEMENTATION APPROACH
==================================================

1. Keep the raw AM input values in state and saved report metadata.
2. Do not directly render them as a combined text blob.
3. Create section-level usage logic.

For each report type, determine where AM inputs should influence output.

Examples:
- QBR Prep:
  - Section 5 SEO Tier Diagnosis
  - Section 6 What We Need to Do Next
  - Section 7 What We Track only if clearly relevant
- Monthly:
  - commentary on performance slide
  - next month priorities
  - strategic initiative notes
- Full QBR:
  - challenge slide
  - opportunity slide
  - tactics slide
  - roadmap / alignment
- Mid-Strategy:
  - immediate focus
  - risk flag
  - next steps
  - client asks / dependencies

==================================================
VISIBLE OUTPUT RULE
==================================================

AM inputs should only appear visibly when one of these is true:
1. they materially improve a section’s interpretation
2. they justify why a recommendation is being made
3. they explain a known anomaly or context
4. they support a challenge/opportunity statement

Even then:
- rewrite them into client-ready language
- keep them concise
- place them where they belong

==================================================
DO NOT DO
==================================================

- do not create one “AM Notes” blob in the report unless explicitly designed
- do not dump hypothesis + audit notes into one cell
- do not repeat the same AM wording across multiple sections
- do not expose raw internal shorthand if it needs rewriting
- do not remove AM input persistence

==================================================
SAVE / RELOAD RULE
==================================================

Keep AM inputs persisted with the report so that:
- reload restores them
- regeneration can reuse them
- they remain editable in the input panel

But again:
- persist raw inputs
- render distributed interpreted output
