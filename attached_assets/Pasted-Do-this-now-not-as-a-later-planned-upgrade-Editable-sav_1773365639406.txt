Editable saved reports are a product requirement. Because of that, positional comment anchors are not safe enough where sections/slides may later be edited or reordered.

Implement stable semantic anchor IDs now for report comments and editable saved-report structure.

PRIORITIES

1. Replace fragile positional anchors where needed
- Monthly Report must move off raw slide:${i} anchors now
- use stable named semantic anchors instead
- examples are acceptable like:
  - monthly:exec_summary
  - monthly:kpis
  - monthly:traffic_trends
  - monthly:conversions
  - monthly:content_work
  - monthly:technical_work
  - monthly:local_visibility
  - monthly:next_steps

2. Review other report types for positional anchor fragility
- if QBR or any other report is using raw positional anchors, determine whether it should also move to stable semantic anchors now
- if a report can remain slide-based, the slide anchors should still be stable semantic IDs rather than pure numeric position wherever practical

3. Preserve comment integrity for editable saved reports
- comments must remain attached meaningfully even if sections/slides are reordered
- comments must not drift due to positional changes

4. Prepare for future section/table refresh capability
Without building the full refresh UI yet, update the structure so report sections/blocks can later support:
- refresh this section
- refresh this table
- compare current vs refreshed
- keep / replace / merge

At minimum, ensure editable saved report structure is moving toward:
- stable block/section identity
- predictable anchor IDs
- future compatibility with block-level regeneration
