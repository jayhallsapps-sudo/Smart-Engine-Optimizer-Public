Objective
Recreate the ORIGINAL “Bi-weekly Report” PDF as a carbon copy. The original PDF is the single source of truth. The most recent generated PDF is wrong and must be corrected. No creative interpretation, no “close enough,” no default styling.

Inputs (provided as attachments in this Replit run)
1) ORIGINAL_TEMPLATE.pdf  (ground truth)
2) CURRENT_OUTPUT.pdf     (what we generated; contains errors)
3) HEADER_IMAGE.(png/svg) (new header asset to use; must match the original header placement)

Non-negotiable rules
- Zero guesswork. If an attribute cannot be extracted reliably from ORIGINAL_TEMPLATE.pdf, raise an error and print exactly what is missing.
- Do not introduce any new colors (especially default link blue). Colors must match the original exactly.
- Fonts must match the original exactly; if the original uses Inter, embed Inter and use it. No substitutions.
- Layout must match the original: margins, positions, indents, bullet glyphs, table geometry, header, footer, line weights.

Required approach (do not deviate)
1) Template-driven generation with extraction
- Parse ORIGINAL_TEMPLATE.pdf using PyMuPDF (fitz) to extract:
  - Page size (points)
  - Text spans with: font name, font size, color (RGB), bbox coordinates
  - Drawing elements: lines, rectangles, fills (for date pill fill + footer line), table borders
  - Bullet glyphs and indentation from bbox x positions
- Build template_spec.json from the extracted data.

2) Background strategy
- Do NOT rasterize the whole page as a background.
- Only reuse assets where needed (header image).
- All text, shapes, and lines must be vector drawn so fonts/colors remain accurate.

3) Header (currently wrong)
- Replace the header with HEADER_IMAGE but match the original’s:
  - exact position (x/y)
  - exact size (width/height in points)
  - exact cropping/clipping (if any)
- No aspect ratio “fit” guesses. Use coordinates extracted from ORIGINAL_TEMPLATE.pdf.

4) Fonts (currently wrong)
- Detect the exact fonts used in ORIGINAL_TEMPLATE.pdf (expected: Inter family weights).
- Embed the font files in the project (ship them with the repo).
- Render text using the same font family + weight + size as the original spans.
- Hard fail if any font fallback occurs.

5) Remove unwanted blues (currently wrong)
- Blue text must never appear unless it exists in ORIGINAL_TEMPLATE.pdf at the same location and for the same content.
- Implement a post-generation scan:
  - Collect all text colors in CURRENT_OUTPUT.pdf
  - Compare to the palette extracted from ORIGINAL_TEMPLATE.pdf
  - If any color exists in output not present in template palette, fail and print:
    page, offending color, the text snippet, bbox

6) Footer (missing)
- Footer must exist as a real footer on every page and match ORIGINAL_TEMPLATE.pdf:
  - bottom divider line: exact y position, stroke color, stroke width
  - footer text: exact content, font, size, color, alignment
- Extract footer line + text styling from ORIGINAL_TEMPLATE.pdf, render them explicitly in output.

7) Date pill gray (wrong shade)
- Extract the exact fill color from ORIGINAL_TEMPLATE.pdf for the date highlight element.
- Render a rectangle (or shape) with the same fill and same bbox.
- Place the date text on top with the same font + size + color + padding.

8) Tables (must match)
- Extract table grid geometry: column widths, row heights, border colors/widths, header fill.
- Render the table with explicit geometry (points), no auto-fit.
- Hard fail if any column width < 80pt or any row height deviates from template by > 1pt.

Validation (mandatory)
Create verify_match.py:
- Render ORIGINAL_TEMPLATE.pdf and NEW_OUTPUT.pdf to images at 300 DPI (use PyMuPDF page.get_pixmap).
- Compute:
  - SSIM score per page
  - Pixel diff heatmap image per page
- Output:
  - overall SSIM average
  - per-page SSIM
  - diff images saved to /diff/
- Fail the build if SSIM average < 0.985 OR any page < 0.98.

Workflow (must follow)
Step A: Build extract_spec.py
- Print the extracted template palette, font list, header bbox, footer line bbox, date pill bbox, and table geometry.
- Save template_spec.json

Step B: Build generate_report.py
- Generate NEW_OUTPUT.pdf strictly from template_spec.json + report data.

Step C: Run verify_match.py
- Output SSIM metrics + diff images.
- Iterate until the threshold is met.

Deliverables
- extract_spec.py
- template_spec.json
- generate_report.py
- verify_match.py
- NEW_OUTPUT.pdf
- /diff/ page diff images
- requirements.txt (pinned versions)
