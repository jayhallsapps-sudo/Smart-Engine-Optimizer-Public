Build the Phase 2 preview, editing, and in-app presentation experience for SmartEO so report output feels first-class inside the app.

IMPORTANT CONTEXT

The following already exist and must be extended, not replaced:
- Phase 2 workflow shell at /workflow
- canonical report registry
- report family split foundations
- existing report pages and preview infrastructure
- native comments system
- contextual finding chat
- current QBS design language and report styling conventions

Do not rebuild the report system from scratch.

CORE OBJECTIVE

Make SmartEO’s in-app report experience strong enough that internal users can review, edit, and present reports directly inside the product without depending on export as the main workflow.

This prompt is not about templates or admin systems yet.
It is about making the current preview/edit/presentation experience feel coherent, intentional, and family-aware.

PRIMARY GOALS

1. STRENGTHEN IN-APP PREVIEW

Requirements:
- make report preview feel polished and intentional inside SmartEO
- preserve existing working preview infrastructure where possible
- improve layout/readability where needed
- keep the right-side comments panel compatible
- keep report-family differences visible and meaningful

2. STRENGTHEN IN-APP EDITING

Requirements:
- preserve current editing capabilities where they already work
- improve the editing experience so it feels native to SmartEO, not like a bolt-on tool
- support section/slide reordering where already feasible
- support direct text edits where already feasible
- avoid unnecessary rewrites of working report pages

3. ADD A REAL IN-APP PRESENTATION / READ MODE

Requirements for slideshow-style reports:
- Kickoff Deck
- Mid-Strategy Deck
- Launch Deck
- QBR

Build a polished in-app presentation mode:
- full-screen or near-full-screen presentation view
- clean slide-to-slide navigation
- no distracting editing chrome while presenting
- suitable for client-facing calls

Requirements for document-style reports:
- Bi-Weekly Report
- Monthly Report
- QBS

Build a polished read/presentation mode:
- clean reading mode
- reduced editing chrome
- strong section navigation where practical
- suitable for walking someone through the report on a call

4. KEEP REPORT FAMILY BEHAVIOR DISTINCT

Requirements:
- do not force slideshow-style and document-style reports into the same presentation behavior
- preserve family-aware rendering differences
- make deck-style reports feel like decks
- make document-style reports feel like documents

5. MAINTAIN DESIGN CONTINUITY

Requirements:
- preserve the current QBS design language as the baseline for report-related styling
- do not introduce a random new visual style
- keep the SmartEO feel calm, professional, and operational
- do not let presentation mode feel like a different app

6. REUSE / COMPATIBILITY RULES

- reuse current preview/edit/report infrastructure wherever possible
- do not replace working report pages unnecessarily
- do not break current report generation or save/load flows
- keep comments compatible
- keep finding chat integrations compatible where relevant
- preserve savedReportId-based comment behavior

7. DEFERRED ITEMS

Do not build in this prompt:
- full template builder
- admin template controls
- full presenter notes system unless a lightweight foundation is very easy
- export overhaul
- deep workflow intelligence changes

8. DELIVERABLES

Build/refine:
- improved in-app preview experience
- improved in-app editing experience where practical
- slideshow-style presentation mode
- document-style read/presentation mode
- cleaner family-aware report output behavior

IMPLEMENTATION REPORT REQUIRED

After building, provide a short implementation report including:
- files changed
- what was reused
- what was refactored
- what was newly added
- how slideshow-style presentation mode works
- how document-style read mode works
- any UX compromises
- any risks or deferred items

SUCCESS CONDITION

A SmartEO user can preview, edit, and present both report families directly inside the app in a way that feels polished, report-type aware, and clearly better than relying on export as the default review/presentation workflow.
