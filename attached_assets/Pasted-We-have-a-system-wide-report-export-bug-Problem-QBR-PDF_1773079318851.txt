We have a system-wide report export bug.

Problem:
- QBR PDF export fails.
- QBR Prep export fails.
- Report generation/download appears unreliable across all report types.
- Fix the export pipeline across the entire reporting system, not just one report.

Scope:
Audit and fix export/generation for every report type currently in the app, including:
- Bi-weekly
- Monthly
- QBR Full
- QBR Prep
- Mid-Strategy
- Any other report/export path currently exposed in the UI

What I want:
1. Find the current export architecture end-to-end.
   - Identify all report generators, export handlers, download buttons, API routes, background utilities, shared helpers, and template/render files.
   - Tell me which parts are duplicated and which parts are shared.
   - Identify the actual root cause(s) of failure, not just the symptom.

2. Refactor to one shared export pipeline.
   - Every report type should go through the same export service.
   - Keep report-specific content/templates separate, but unify generation, validation, rendering, file creation, and download handling.
   - Do not leave one-off export logic scattered across components.

3. Make export server-side and deterministic.
   - If any exports are currently being generated from fragile client-side DOM capture, html2canvas, or ad hoc jsPDF logic, replace that with a stable server-side export flow.
   - Preferred approach for PDF: server-rendered HTML + Playwright/Puppeteer print-to-PDF.
   - Export should not depend on what is visible on the user’s screen.
   - Export should not include UI-only controls like add-row buttons, edit icons, hover states, or preview-only chrome.

4. Add a preflight validation step before export.
   - Validate required data exists.
   - Validate the report type is recognized.
   - Validate all async data is resolved before rendering.
   - Validate charts/tables/images/fonts are ready.
   - Return a useful error message if export cannot proceed.
   - Never fail silently.

5. Make report rendering export-safe.
   - Add a dedicated export/print mode.
   - Ensure long tables paginate correctly.
   - Prevent clipped content, overlapping sections, blank pages, or missing charts.
   - Ensure page breaks are intentional.
   - Ensure headers, section spacing, and typography are consistent across report types.
   - Ensure dark-mode/app theme styling does not leak into exports unless explicitly intended.

6. Fix async rendering issues.
   - Wait for all report data, chart rendering, and assets before generating files.
   - Add an explicit “report ready” signal before PDF creation.
   - Prevent race conditions where the export fires before content is fully mounted.

7. Harden download behavior.
   - Ensure every export returns the correct MIME type, filename, and non-empty file buffer.
   - Ensure downloads work from both preview mode and final report mode.
   - Ensure loading, success, and failure states are clear in the UI.

8. Add logging and diagnostics.
   - Log export start, report type, format, completion, duration, and failure reason.
   - Make it easy to see whether failures are data, render, timeout, asset, or filesystem related.

9. Add regression tests for all report types.
   - Create one fixture/export test per report type.
   - Each test should verify:
     - export endpoint returns 200
     - file buffer is not empty
     - file size is above a minimum threshold
     - PDF has at least 1 page
     - expected report title appears in the exported output
   - Add one failure test for missing required data.
   - Add one test for long-table pagination.

10. Clean up the UI wiring.
   - Make sure every download button points to the correct unified export path.
   - Remove dead/legacy export buttons or handlers.
   - Ensure the preview uses the same underlying report data contract as the export.

Technical direction:
- Create a shared export service, something like:
  - buildReportData(reportType, reportId, options)
  - validateReportData(reportType, data)
  - renderReportForExport(reportType, data, exportOptions)
  - generatePdfFromHtml(html, options)
  - streamDownload(file, metadata)
- Each report type should only define:
  - its data mapping
  - its template/layout
  - its report-specific rules
- Everything else should be shared.

Important implementation rules:
- Do not do a narrow patch that only makes QBR pass.
- Do not leave client-side PDF hacks in place if they are the source of instability.
- Do not ask me for approval at each step.
- Inspect the codebase, implement the fix, and tell me exactly what you changed.

Definition of done:
- Every report type can be previewed and downloaded successfully.
- PDF export works for QBR and QBR Prep.
- Export works consistently across all reports from the current UI.
- Failures return useful messages instead of breaking silently.
- Tests exist so future report changes do not break export again.

Final output back to me:
- Root cause summary
- Files changed
- What was refactored
- What report types were verified
- Any remaining risks
