REQUIREMENTS

1. MONTHLY
Monthly must not output raw task strings.

- narrate completed work clearly

2. QBR FULL
QBR Full must narrate:
- performance trends
- strategic wins/losses
- technical and content priorities
- opportunities and risks
- client-facing executive summary language grounded in actual inputs

3. QBR PREP
QBR Prep can be more internal, but still must:
- translate raw evidence into usable strategic notes
- identify likely talking points
- surface anomalies, wins, risks, and required explanations

4. MID-STRATEGY
Mid-Strategy must narrate:
- what is changing in performance or execution
- what needs to be adjusted
- what priorities should shift next

5. SOURCEFACTS
For every report type, persist:
- matched source record IDs
- normalized evidence packet
- provider used
- narration used true/false
- prompt version
- generated timestamp

6. DEBUG PANEL
For every report type, add a debug/evidence panel showing:
- provider used
- narration used
- matched record counts by section
- normalized evidence packet
- fallback triggered yes/no
- manual edits count
- source IDs where available

7. STRICTER FALLBACK LANGUAGE
Replace vague filler with honest, specific fallback wording.

Examples:
Bad:
- “Ongoing technical maintenance monitored this period.”
- “Continued optimization efforts are underway.”

Better:
- “No completed technical fixes were logged during this reporting window; current focus is on resolving 4xx errors and pagination issues identified in the latest crawl.”
- “No optimization updates were completed during this period.”

8. DETERMINISTIC NON-AI FALLBACK FORMATTER

For example:
Raw:

Deterministic fallback:
- “Completed title tag and meta description updates on /drug-rehab-los-angeles/.”

AI should remain preferred.
But non-AI fallback should still produce clean client-safe wording.
