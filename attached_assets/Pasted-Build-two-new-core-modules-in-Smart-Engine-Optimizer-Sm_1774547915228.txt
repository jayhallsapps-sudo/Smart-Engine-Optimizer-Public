Build two new core modules in Smart Engine Optimizer (SmartEO) called Theme and Templates. Place both at the end of the core modules list in the SmartEO Command Center. Theme must appear first. Templates must appear second. Remove Templates from the left sidebar entirely. Relocate it. Do not delete it. Do not leave duplicate navigation behind.

Non-negotiable outcome:
SmartEO must gain a real centralized design system and a real reusable slide/page template system. I do not want a shallow settings screen. I do not want disconnected controls. I do not want a half-working visual editor. I do not want styling spread across the app after this. I want one clear theme system that governs presentation across the system, and one clear template system that governs report/page/slide structure across the system.

Core requirement 6: Existing slide/page analysis
Do not build the slide/page type library blindly.

You must inspect the slide/page/report structures already present in SmartEO and use them to inform the builder.

Required behavior:

I do not want a blank “template builder” disconnected from the actual system. I want the existing SmartEO slide/page reality turned into a reusable system.

Core requirement 7: Theme inheritance
When a theme is published, the active theme must apply across the entire presentation layer of SmartEO.

Theme must apply to:

Monthly deck previews
QBS previews
QBR previews
Bi-weekly previews
current and future report/deck/document previews
slide/page previews inside Templates
print views
PDF export styling where supported
DOCX/Google Docs token mapping where supported
shared presentation components
tables and structured output components where appropriate

Rules:

remove scattered hardcoded visual values where they should now inherit from Theme
preserve structural/layout logic while migrating presentation styling to theme tokens
use safe fallbacks if a token is missing
do not break existing outputs
