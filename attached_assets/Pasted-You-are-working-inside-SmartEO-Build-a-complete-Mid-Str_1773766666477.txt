You are working inside SmartEO. Build a complete Mid-Strategy reporting workflow consisting of two connected systems:

Evaluation Sheets module

Mid-Strategy Report generator

The goal is to make this work the same way our other report systems do in terms of saved records, editability, rendering quality, and printable/exportable presentation, but adapted for a slide-deck style output.

The system must be reusable for any client. Bliss is the seeded example and reference structure, not a hardcoded one-client build.

PART 1: CORE OBJECTIVE

We need a robust feature that lets a user:

create and save a batched Mid-Strategy Evaluation Sheet set

populate it automatically from integrations, web retrieval, formulas, and crawl data

support manual upload/import of Screaming Frog crawl exports until SmartEO has its own crawl engine

preserve formulas, rankings, and chart-ready outputs

link a saved evaluation batch to a Mid-Strategy Report record

generate a slide-deck-style report from that linked evaluation batch

allow manual editing of all generated text fields after generation

preserve charts, tables, and visual sections inside the report

support export/print in the same polished way our other reports do

Do not build this as a one-off Bliss-only feature. Build it as a reusable system.

PART 2: HIGH-LEVEL PRODUCT REQUIREMENTS
A. New module: Evaluation Sheets

Add a new core module in Command Center called:

Mid-Strategy Evaluation Sheets

This module should sit alongside the rest of the reporting and report-prep infrastructure, not inside the report generator itself.

The Evaluation Sheets module is where the user creates and manages the source data batch that later powers a Mid-Strategy Report.

Each saved evaluation batch must represent one named project snapshot for one client.

Example:

Client: Bliss Recovery

Eval Batch Name: Bliss Mid-Strategy March 2026

Status: Draft / Linked / Report Generated

Each evaluation batch must be saveable independently from the report.

B. Linking workflow

Once an Evaluation Sheet batch is created and saved, the user must be able to link it to a Mid-Strategy Report.

In the Evaluation Sheets list view, add an action like:

Link to Mid-Strategy Report

When clicked, the system should:

create a new report-generation record

assign the selected evaluation batch to that report

name the report based on the batch name unless manually overridden

place the report into the Mid-Strategy Report list as “Not Generated Yet” or equivalent pending state

Then, when the user opens that pending report, the system generates the Mid-Strategy slide deck using the linked evaluation batch.

This linkage is one-directional in terms of data source:

Evaluation batch is the source of truth for metrics, tables, charts, and citations

Mid-Strategy Report is the presentation layer built from that linked source

PART 3: NON-NEGOTIABLE AUTOMATION RULE

The Mid-Strategy Evaluation Sheets must be fully automated wherever possible.

The user should not have to manually populate evaluation metrics. Every field in the Evaluation Sheets must be sourced from one of the following:

an existing SmartEO integration

a crawl run inside SmartEO when available in the future

a manual Screaming Frog export upload for crawl-based data until SmartEO has its own crawl feature

a web retrieval task

a system-generated formula or calculation

a derived rollup from imported raw data

an Ahrefs or SEMrush fallback where uploaded crawl data does not contain required information

Manual entry should be limited to:

selecting the client

selecting competitors

uploading Screaming Frog crawl exports where needed

optional overrides for page category classification

optional editing of report narrative after generation

optional editing of navigation and IA structures for recommendation slides

Do not build the Evaluation Sheets as manual spreadsheet-entry tools. Build them as auto-populated analytical sheets backed by integrations, uploads, and formulas.

source fields or rows used

supporting metrics used

generation timestamp

The user does not need to see ugly system citations in the slide itself, but there should be an internal trace mechanism so we know:

which slide text came from which sheet

which chart came from which summary table

which narrative used which metrics

For example:

Slide 8 homepage concentration bullets → Clicks Distribution

Slide 9 sessions concentration bullets → Traffic Distribution

Slides 4–7 competitor narratives → Main Evaluation

IA slides → manually entered IA model plus optional current menu source

Also allow an optional “show sources” developer/debug view.

PART 27: ACCEPTANCE CRITERIA

The feature is done only when all of the below are true:

I can create a new Evaluation Batch from Command Center.

I can open tabs for Main Evaluation, Crawl Data, Pivot Table 2, Clicks Distribution, and Traffic Distribution.

I can upload a Screaming Frog export and use it as the crawl source.

The uploaded crawl is parsed into Crawl Data.

Missing crawl fields are enriched from Ahrefs, SEMrush, GSC, or GA4 where possible.

I can enter/select client and competitors without manually filling metrics.

Main Evaluation metrics populate from integrations, web retrieval, uploads, and formulas.

Summary tables and chart inputs recalculate correctly.

I can link a saved evaluation batch to a Mid-Strategy Report.

The linked report appears in the report list as pending/not generated.

Opening the pending report generates the full Mid-Strategy slide report.

The report includes all required sections from the Bliss example deck.

All text sections are editable after generation.

Competitive analysis charts render from evaluation data.

Clicks Distribution and Traffic Distribution charts render from summary tables.

Current and future menu visuals render as actual visual mockups, not plain bullets.

IA blueprint slides render parent/child slug structures clearly.

“What’s Next” sections are editable.

Export/print works cleanly.

Manual text edits persist after save.

Citation/source traceability exists internally for generated insight blocks.

Refresh Data supports rerunning full or partial data jobs.

The system is built generically for future clients, not just Bliss.

FINAL IMPORTANT RULES

Do not flatten the evaluation sheets into a simple form.

Do not treat the IA slides as plain text.

Do not hardcode Bliss values.

Do not wipe manual edits on regenerate.

Do not skip charts or replace them with placeholders.

Do not make “Prepared by” auto-populate with a random user.

Do not make the Mid-Strategy report live inside the Evaluation Sheets module.

Do not require manual metric entry for evaluation data that can be pulled, uploaded, or calculated.
