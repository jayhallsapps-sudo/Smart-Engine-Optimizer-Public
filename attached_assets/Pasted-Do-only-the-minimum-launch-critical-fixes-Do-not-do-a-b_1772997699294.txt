TASK 1 — Harden the bootstrap token flow
==================================================

Current problem:
The unauthenticated bootstrap endpoint returns the shared internal token to any client that can hit it. That is too loose.

Goal:
Tighten this without redesigning the full auth system.

Requirements:
1. Restrict /api/auth/bootstrap so it only responds to same-origin browser requests.
2. Reject bootstrap requests when Origin or Referer is missing or clearly not from the app’s own host, unless running in local dev.
3. Do not return the token to cross-origin requests.
4. Keep the frontend working without changing the user flow.
5. If a request is rejected, return 403 with a clear message.

Implementation guidance:
- use request host / origin / referer validation
- allow localhost / local dev origins in development
- do not redesign the entire app auth model
- do not break queryClient bootstrap in the real app

Return proof:
- exact code
- one same-origin bootstrap request that passes
- one cross-origin bootstrap request that fails
