Build a new SmartEO workflow called Mid-Strategy SEO Report.

This is NOT a normal report generator. This is a spreadsheet-backed slide-deck workflow.

The most important architectural rule:
The slide deck must be generated from one shared spreadsheet workbook that contains multiple tabs used by this report. The workbook is the intermediate source of truth for the report. Do not bypass it. Do not hardcode values directly into slides from raw APIs unless explicitly required as a fallback.

This report is more complex than Monthly, QBR Prep, and Full QBR because the spreadsheet tabs drive what appears in the deck.

==================================================
PRIMARY GOAL
==================================================

Build the Mid-Strategy SEO Report as a SmartEO workflow that:

1. uses the attached Mid-Strategy deck as the fixed slide structure
2. uses the attached spreadsheet workbook as the data backbone
3. reads and writes the required data into the correct tabs/ranges of that workbook
4. never invents missing values
5. leaves missing fields blank, dashed, or marked as Manual entry needed
6. deeply analyzes the client website and connected SEO sources
7. uses shared save/load/autosave infrastructure
8. uses shared current + comparison crawl selection
9. renders a branded editable slide preview
10. exports cleanly to PPTX
11. uploads cleanly to Google Drive / Google Slides workflow

==================================================
CRITICAL ARCHITECTURE RULE
==================================================

This report must be built as a 3-layer system.

LAYER 1 — SOURCE NORMALIZATION
Pull and normalize all usable source data from connected integrations.

LAYER 2 — SPREADSHEET BUILDER
Populate the required tabs/cells/ranges in the shared spreadsheet workbook for this client/report run.
The workbook is the intermediate truth for the report.
Do not guess values.
Do not silently skip required fields.
If data is unavailable, leave blank / em dash / Manual entry needed based on the target cell’s intended use.

LAYER 3 — SLIDE GENERATOR
Generate the Mid-Strategy slide deck from the spreadsheet-backed report state, not directly from raw APIs.

This separation is mandatory.

==================================================
NON-GOALS
==================================================

Do NOT:
- build the slides first and “figure out the spreadsheet later”
- hardcode benchmark values into slides
- invent missing competitive metrics
- create a snowflake save system
- create a separate crawl system
- add extra sections or slides
- silently omit slides or spreadsheet rows because data is missing
- make assumptions that are not supported by data

==================================================
SOURCE OF TRUTH
==================================================

Use:
1. the attached Mid-Strategy SEO deck as the fixed slide structure
2. the attached shared spreadsheet workbook as the fixed data workbook
3. the workbook’s relevant tabs/ranges as the backbone for sections of the deck

Important:
- it is ONE workbook with multiple tabs, not three separate files
- be very careful about tab names, ranges, and dependencies
- the same workbook supports multiple report sections
- changing or populating the wrong tab/range will corrupt the report logic

Before implementing data writes, inspect the workbook structure carefully and map:
- each relevant tab
- each relevant range
- the purpose of each range
- which slide(s) depend on that tab/range

Do not proceed with implementation until that mapping is clear.

SPREADSHEET-BACKED IMPLEMENTATION RULES
==================================================

This is the most important section.

You must first inspect the workbook and produce an internal mapping of:
- relevant tab names
- relevant ranges
- which report section/slide each tab/range supports
- what source should populate each field or cluster of fields
- which fields are raw-source fields
- which fields are calculated/scored fields
- which fields are manual-only fields

Implementation requirements:
1. Build workbook population logic tab-by-tab, not cell-by-cell spaghetti
2. Normalize data before writing into workbook-backed report state
3. Never write guessed values into workbook fields
4. If a field cannot be populated:
   - leave blank
   - or use em dash
   - or use Manual entry needed
   depending on the intended field style
5. Preserve workbook-backed state in SmartEO so the user can regenerate slides without losing manual corrections
6. Allow manual overrides after generation
7. If the workbook contains formulas or scoring relationships, preserve their logic conceptually in SmartEO’s workbook-backed state
8. If the workbook relies on values from connected benchmark tabs, populate only from available source data

Important:
Do not blindly scrape random workbook cells.
Understand the workbook structure first.
